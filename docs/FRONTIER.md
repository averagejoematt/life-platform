#### Story acceptance (promote verbatim)

##### VS-1 — training: a variant-slot registry pins one exercise per slot for a program block

Why: accessories were fixed per template with no plan across blocks; several trained muscle regions dropped to zero sets when the block started.
- `training/variant_slots.py` holds heads, variants (template ids, aliases, head weights, pattern, bodyweight-tier gate read from the redlines) and slots; the block-2 table is its initial content.
- `program_structure` templates derive their slot list from the registry (derivation-guard test over the SET of templates).
- Contract test: every template exercise maps to a registry variant; every tracked head has ≥ 1 slot.
- A block pin row (`SOURCE#training_block`, `BLOCK#<start>`) is written once per block; phase-taxonomy class registered.
- Generator, planner and chat gate resolve through one function (tested: all three read one variant).
- **Live proof:** the first nightly pre-draft after the block-2 start carries `slot_id` + the pinned variant on every exercise, and the pin row exists in DDB.

##### VS-2 — training: per-head coverage is counted from sets over 28 days

Why: the only volume reader is per muscle with a 0.5 secondary credit that roughly doubles arm counts; no reader sees a head at zero.
- `head_coverage()` excludes warm-up and untagged ramp sets (rule documented in the docstring) and resolves aliases.
- Unmapped templates are reported by name, never dropped.
- Fixture = real stored Hevy rows (the wire), with a mutation control that re-includes ramp sets and fails.
- The weekly report prints one line per head below its floor.
- **Live proof:** the first weekly report after deploy lists coverage per head and names any head below floor, matching a hand count of the same week's sets.

##### VS-3 — training: slots rotate at a block boundary by a deterministic rule

- The next variant is the eligible one whose primary head has the lowest trailing-8-week direct count; ties → oldest last-performed; a variant holds a slot ≤ 2 consecutive blocks unless it is the only one for its head.
- A rotation that leaves a tracked head with 0 slots is refused.
- Bodyweight-tier-gated variants are ineligible until the gate is met (gate value read from the redlines).
- Tests: pinned inside a block; lowest-covered head wins; zero-slot refusal; tier ineligibility.
- **Live proof:** the block-3 pin row records each rotation with its reason string, and no head has 0 slots.

##### VS-4 — training: a novelty budget limits novel-again variants per session and per boundary

- Counts only variants with no exposure in the novel-again window; near-neighbour swaps inside it are not rationed.
- ≤ 1 per session and ≤ 3 per boundary (values from the redlines); the novelty critic names the session that breaks it.
- A novel-again variant takes the re-entry rule for exposures 1–3 (effort cap, rep cap).
- **Live proof:** the block-3 pin row's `novelty` block is within budget and each novel-again variant's first draft carries the exposure-1 cap.

##### VS-5 — training: the green-tier optional block is authored, counted as planned, and never graded as extra

Why: the self-added-volume report fired three complete weeks running on the owner's drive to do more (owner ruling #4111); the program had no planned outlet.
- IR marks optional exercises `optional: tier_green` and their sets `role: bonus`; the block is printed last with exact loads.
- The picker chooses ≤ 3 movements from the lowest-covered heads; never an anchor, never axial, never a load increase, never a novel-again exposure 1–3.
- Per-session and weekly caps read from the redlines; Flex sessions draw from the same weekly cap.
- `adherence_calc` scores optional sets as `planned_optional`; `self_added_volume` measures only what exceeds prescription + the optional ceiling; the weekly report prints "optional sets used: N of cap" and bonus uptake.
- The optional block is withheld when the protein, readiness or pain tripwire fires.
- The generator's per-session set ceiling reads the redline (base and with-optional values), no literal.
- **Live proof:** a green-tier session's routine carries the block; the next end-of-week report counts its sets as planned optional, and the self-added net excludes them.

##### VS-6 — training: the commit gate judges each set by its declared role (residual of #4065)

Why: #4308 accepted the program's own back-offs by position; a third back-off, the chat path's every-set back-off floor, and a movement with no template id (which checked no floor at all) remain.
- Every IR set carries a role; floors per role (top/work, back_off, bonus, cal); a roleless set is judged at the full floor.
- Comparison on the implement's grid in the loaded unit, with a round-trip tolerance.
- A missing template id is a named failure, not a silent pass.
- Tests: top + 2 back-offs passes; a back-off exactly at the floor after a unit round trip passes; a volume set below its floor fails; a bonus back-off passes; roleless → full floor; missing id → named failure.
- **Live proof:** a committed routine with a third back-off and a bonus set passes the gate, and the stored gate result names each set's role.

##### VS-7 — training: loads progress by an engine-authored double progression (the gain rule gets a reader)

Why: "loads hold, gains taken only when offered" has no module that offers a gain; the owner raised loads himself instead, which the grader counted as breaches.
- `training/load_progression.py`: trigger = reps at the top of the range on 2 consecutive exposures of the same type at the prescribed load; RPE acts only as a veto (last graded set > ceiling + 1); a pain flag on the pattern or a novel-again on-ramp refuses.
- +1 rep per set to the range top, then the smallest implement step; a step larger than the redline's step cap is taken as reps first; ≤ the redline's weekly e1RM cap per anchor while inside the re-entry window.
- No nutrition clause gates an earned step (owner decision OD5); a missed step on an under-fuelled day is not counted as a stall.
- Self-raised load at or under the ceiling becomes the next floor and is reported as `self_added_load`.
- The reason string goes into the exercise note (≤ 120 chars).
- **Live proof:** after two qualifying exposures, the next nightly draft for that movement carries the +1 rep or the load step with its reason string.

##### VS-8 — training: prescriptions are feasibility-checked and intensity grading reads only exercise-scoped ceilings

Why: one volume prescription required a strength level above the owner's own band record; a routine-level effort cap written for one lift graded four other lifts.
- Authoring refuses a load whose Epley-with-reserve estimate exceeds the band e1RM, with a named reason.
- Ceilings come only from exercise-scoped sources; a routine-level note never grades another exercise.
- The last working set is graded; untagged ramp sets are excluded; a set above prescribed load is graded `load_override`, not an intensity breach.
- Every intensity-adherence number ships with the same-load RPE SD and n beside it.
- **Live proof:** the first lifting session after deploy stores intensity adherence with no set graded against another exercise's ceiling and any above-prescription set tagged `load_override`.

##### VS-9 — training: the carry-forward hold covers gaps up to the detraining line, and re-entry is graded by gap (follow-up to PR #4417)

Why: PR #4417 holds a this-cycle load only when the record gap is under one week; beyond that it falls back to the week-1 entry ramp, recreating #4408 after a single missed week.
- The hold applies up to the owner's detraining line (the same threshold `anchor_discount` uses), read from one constant.
- Gaps between the detraining line and the novel-again line enter at `load_anchoring.entry_pct_of_band_best`.
- Beyond the novel-again line: the ramp with the exposure-1–3 effort and rep caps; pace keyed to exposures, not program weeks.
- Nearest-band anchors are capped by band distance and age (redline values); beyond the caps the movement has no anchor and is not chosen over an anchored variant.
- **Live proof:** a nightly draft for an anchor last performed 8–27 days earlier carries `hold.applies == true`.

##### VS-10 — training: a core-pattern guard and an automatic axial pain swap

- Each core movement carries one tag (anti-rotation, anti-lateral-flexion, anti-extension, carry); the same tag never lands on consecutive calendar days; no heavy carry the day before lower-heavy; core is placed last.
- A back or hip pain flag on an axial pattern writes a block AMEND row swapping the volume squat and an early-morning hinge to their listed non-axial variants for the rest of the block.
- **Live proof:** a draft the day after a carry session carries no carry; a test pain flag in a fixture produces the AMEND row (live proof waits for the first real flag and says so).

##### VS-11 — training: a 5 am note linter at commit

- Refuse to commit a routine with any note over 120 characters, an exercise 1 without the three tier lines, or a note containing a %-of-load instruction.
- The rationale lives in the packet, never in Hevy notes.
- **Live proof:** the next committed routine's stored lint result is clean, and a deliberately long note is refused in the chat path with a named reason.

#### Story acceptance (promote verbatim)

##### CS-1 — training: every Hevy cardio block carries a block-scoped heart rate with its provenance (extends #4412)

- A Garmin or WHOOP record inside the session window whose duration matches one block within tolerance becomes that block's HR (`garmin_block` / `whoop_block`); a record spanning two blocks is `merged` and assigned to neither; a lifting session's HR is never borrowed.
- Every block row carries `hr.provenance` including `none`.
- Fixtures from real stored rows: a merged two-block record; a treadmill block with a WHOOP walk; a bike block with none.
- **Live proof:** after the owner starts a watch activity for a bike block, that day's recent-aerobic read shows the bike block with `garmin_block` provenance.

##### CS-2 — training: the draft reads named aerobic quantities — floor hours, weight-bearing hours, hard minutes — and the 90-minute "z2 floor" retires (residual of PR #4418)

Why: PR #4418 wires total aerobic minutes into the draft under the old "z2" name and compares them with a 90-minute floor that is meaningless next to the weekly walking floor.
- `shared_quantities` publishes `floor_hours_wk`, `wb_hours_wk`, `nwb_hours_wk`, `wb_delta_wk`, `hard_minutes_7d`, `gray_minutes_7d`, `standalone_walks_wk`, each `None` with a reason when unreadable.
- Tempo, interval and run minutes are excluded from `floor_hours_wk`.
- `GeneratorInputs` takes the named quantities; the 90-minute floor and its "walk more" text are removed; a guard test over the SET of callers forbids literal values.
- **Live proof:** the next nightly pre-draft's `inputs_snapshot` carries the named quantities with values matching that day's recent-aerobic layer, and no "z2 floor" line.

##### CS-3 — training: personal aerobic zones from reserve heart rate, updated by tests

- `aerobic_zones` computes zone bounds from the 14-day resting median and a reference max (validated peak or a population floor), with the redline's bounds as the provisional values.
- After three fixed-workload bike tests, the steady-zone top is personalised by the drift rule.
- The platform's percent-of-max zones are not used for prescription (documented).
- **Live proof:** the packet shows zone bounds with their basis and as-of date; they change after the third bike test.

##### CS-4 — training: a conditioning stage state machine with computed entry gates, regressions and a walking co-gate

- Registry of stages, gates, doses and regressions, values read from the redlines.
- Weekly evaluation writes STATE, TRANSITION and one EVAL row per week (dead-man: a missing EVAL row is reported).
- Gates return `met / not_met / unknown`; `unknown` never passes and never renders as `not_met`.
- A floor-missed week suspends the next unlock; regression beats progression in the same week.
- Stage 3 cannot open while the owner's interval-wording decision is unratified or the medical record lacks the listed tests.
- **Live proof:** the first Monday after deploy writes an EVAL row whose gate values match the week's recent-aerobic numbers, with the block-HR gate reading from CS-1.

##### CS-5 — training: the generator authors conditioning from the stage, and never above it

- The stage piece is authored only on the tier and stage that allow it; interval and tempo minutes replace steady minutes, never add.
- No tempo or interval block within 24 h before a heavy lower session; on a red day conditioning is the first thing subtracted.
- A hand-drafted block above the current stage is refused with a named reason.
- **Live proof:** the first draft after Stage 2 opens carries the stage piece on an allowed day and none the day before lower-heavy.

##### CS-6 — training: the walking ramp is computed on weight-bearing hours, and the walk heart-rate ceiling is personal

- `wb_delta_wk` is reported every week; no cap applies up to the redline's no-cap line; above it the ramp cap applies; only a pain flag acts.
- `recent_aerobic`'s over-ceiling flag reads the redline field, not a constant; the ceiling is re-derived every 4 weeks from the last walks by the documented rule, with n and as-of.
- `walking_overshoot` reads the new target and permitted values and no longer flags a permitted week.
- **Live proof:** the next weekly report shows weight-bearing and non-weight-bearing hours separately, and the walk flag count reflects the redline ceiling.

##### CS-7 — training: a long-walk slot is classified, checked and exempt from the 75-minute default

- A Strava walk ≥ the classifier length is a long walk; ≤ 1 per week is the slot.
- Checks: elevation per mile, length vs the 28-day pain-free maximum plus the step, the absolute cap by bodyweight band, not within 24 h before lower-heavy; a next-morning pain question.
- The slot walk is exempt from the 75-minute flag; a second long walk in a week is reported.
- **Live proof:** the next weekend long walk appears as `long_walk_slot` with its checks and no 75-minute flag.

##### CS-8 — training: treadmill speed, grade and rails, and bike level and cadence, are structured fields

- Note tokens are parsed; the existing free-text forms are parsed tolerantly and marked `parsed_from: free_text`.
- A "rails" note marks the session as not counting toward grade progression.
- Grade/pace caps and the one-change-per-week rule read these fields.
- **Live proof:** the next treadmill block's row carries speed and grade as numbers matching the note.

##### CS-9 — training: the run gate is evaluated weekly, starting well before the weight gate

Why: no module evaluates the run gate today; its four-week history clause cannot be computed on the day the weight gate is reached.
- A weekly evaluation stores weight, the four-week weight-bearing series, pain-free status and Stage-4 completion.
- The on-ramp is a stored state that advances only after two sessions with a low next-morning pain score; run minutes count double in the ramp and never toward the floor.
- The wording is read from the redline; the evaluator refuses to open the gate while the owner's wording decision is pending.
- **Live proof:** the first weekly EVAL row after deploy carries the run-gate block with `open: false` and the weight-bearing series.

##### CS-10 — training: the nightly draft's readiness tier comes from the recovery colour, sleep and pain, and deload triggers use 7-day means (with #4416)

Why: the nightly draft hard-codes a mid tier; a readiness tool demotes on an activity streak; the recovery tripwire computes only consecutive low days.
- Tier = red if recovery is red, sleep is below the redline's short-sleep line, or a named-site pain flag is active; green if recovery is green, sleep meets the line and no pain; otherwise the plan.
- Bands are re-checked monthly against the personal-baselines percentiles; drift beyond the redline margin switches to the personal values.
- Training-stress balance, duration-proxy load, ACWR and streaks are removed from the tier (they may be displayed).
- Deload early triggers: 7-day recovery mean, 7-day HRV vs baseline, resting-HR rise, two-anchor e1RM drop, two pain sites in 14 days.
- The tier is graded as a forecast: after the session, the morning's real colour is recorded against the branch run.
- **Live proof:** the next nightly draft's `inputs_snapshot` carries the computed tier and its three inputs, and no streak term.
